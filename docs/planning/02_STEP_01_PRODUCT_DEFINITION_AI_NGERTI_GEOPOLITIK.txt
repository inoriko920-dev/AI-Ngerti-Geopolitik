2. Product Statement
AI Ngerti Geopolitik adalah aplikasi desktop Windows untuk creator/editor video geopolitik dan dokumenter yang menyusun draft edit otomatis dari Scene DOCX, aset Axxx, narasi, dan subtitle, lalu memberi kontrol manual penuh untuk review, koreksi, validasi, dan export final yang stabil; produk mempertahankan workflow penting AAVC dan memakai UI AAVC sebagai target visual 1:1, tanpa menjadikan pengguna operator FFmpeg atau membangun NLE umum dari nol.
	Field
	Nilai

	Masalah
	Produksi video naratif mengandung banyak pekerjaan mekanis berulang; pendekatan AAVC lama juga terlalu banyak membuat timeline/preview/render behavior custom sehingga maintenance dan parity sulit.

	Primary User
	Creator/editor dokumenter, geopolitik, sejarah, explainer; tidak harus programmer.

	Primary Value
	Dari input terstruktur ke draft edit yang layak direview, dapat dikoreksi manual, dan dapat diekspor secara repeatable.

	Platform
	Windows 11 x64 V1.

	Distribution
	Portable folder multi-file dalam satu ZIP; bukan installer/single-file sebagai default V1.

	UI Contract
	AAVC frozen UI/UI implementation menjadi target 1:1; tidak redesign.



3. Product Goals
G-001 — Mengurangi pekerjaan mekanis penyusunan puluhan/ratusan visual berdasarkan struktur scene dan Asset ID.
G-002 — Memberi draft otomatis yang konsisten tetapi seluruh keputusan penting tetap dapat dikoreksi manual.
G-003 — Meningkatkan stabilitas dibanding pendekatan editor custom lama dengan memisahkan kebutuhan khas produk dari primitive multimedia umum.
G-004 — Membuat preview, timeline, persistence, recovery, dan export dapat dipercaya untuk project nyata, bukan hanya demo/test tipis.
G-005 — Menyediakan AI editing yang bounded, tervalidasi, undoable, dan tidak mempunyai jalur mutasi tersembunyi.
G-006 — Mempertahankan pengalaman UI AAVC agar pengguna tidak perlu belajar tampilan baru saat berpindah ke repo baru.
G-007 — Menghasilkan build Windows portable yang dapat dipakai tanpa tool developer.
G-008 — Menjaga proyek dapat dilanjutkan lintas AI/sesi melalui source-of-truth, decisions, tests, dan handoff.

6. Primary dan Supporting Workflows
WF-001 — PRIMARY: Buat Project sampai Editor Siap
Trigger: pengguna memiliki Scene DOCX dan folder aset.
Preconditions: aplikasi berjalan; input dapat dipilih; project baru belum aktif.
Inputs: Scene DOCX, folder aset; narration/SRT opsional.
Happy path: Proyek Baru → pilih DOCX → pilih folder aset → aplikasi parse/bind/validate → review import → tambah narration/SRT opsional → pilih lokasi project → save atomic → timeline/editor terbuka.
Alternatives: user dapat membuka project ANG yang sudah ada; legacy importer terpisah bila diaktifkan.
Errors/recovery: DOCX invalid, missing/corrupt asset, media unsupported, atau save path gagal menghasilkan error actionable dan tidak membuat fake success.
Output: project aktif yang tersimpan, timeline canonical, validation status.
Completion: editor terbuka dengan scene pertama/keadaan valid dan project dapat disimpan kembali.
WF-002 — AUTO EDIT
Trigger: user meminta AUTO EDIT pada project yang lolos preflight.
Preconditions: project valid; provider credential tersedia bila AI digunakan; manual editor tetap tersedia bila AI offline.
Flow: context builder → request Gemini → structured Edit Plan → schema/semantic/stale validation → dry run → apply sebagai transaction → preview hasil → Undo bila tidak sesuai.
AI dilarang mengubah credential, project path, output folder, atau user lock tanpa policy/izin.
Failure: timeout/quota/key invalid/invalid plan tidak boleh menghasilkan partial mutation atau project korup.
WF-003 — Review dan Koreksi Manual
User seek/play preview, memilih scene/asset, mengubah order/duration/split/motion/subtitle/marker/In-Out/relink sesuai fitur yang didukung.
Semua perubahan project masuk history dan dapat Undo/Redo.
UI mengikuti AAVC 1:1 sehingga lokasi/hierarchy workflow tetap familiar.
Preview menampilkan keadaan canonical yang sama yang menjadi basis export sejauh engine memungkinkan.
WF-004 — Validation dan Relink
Aplikasi menampilkan issue severity, target, dan tindakan recovery.
User dapat memilih file/folder pengganti; binding diperbarui setelah validasi.
Blocker penting mencegah export; warning tidak disamarkan sebagai success.
WF-005 — Save, Reopen, dan Recovery
Save menulis project secara atomic; unsaved guard mencegah kehilangan perubahan.
Close/reopen mempertahankan state penting.
Jika crash terjadi, recovery snapshot dapat ditawarkan tanpa menimpa project sumber secara korup.
WF-006 — Export
Preflight validation → pilih full/selection + preset → render background job → progress/cancel → verify output → success state hanya bila file final valid.
Cancel/failure tidak boleh meninggalkan status success palsu atau merusak project.
WF-007 — Jalankan Build Portable
User mengunduh satu ZIP, mengekstrak seluruh folder, menjalankan executable utama, lalu open/create project tanpa memasang Python/dev tools.
Normal operation tidak mengharuskan admin atau path drive tertentu.
WF-008 — Migrasi Legacy AAVC (SHOULD)
User memilih project AAVC lama; importer membaca source secara read-only.
Aplikasi memetakan behavior EXACT/APPROX/UNSUPPORTED dan memberi compatibility report.
File legacy sumber tidak diubah.

DATA-003 — Credential: raw Gemini key tidak boleh berada dalam file project, repo, diagnostics, screenshot, atau log. Penyimpanan aman final ditentukan pada arsitektur.
DATA-004 — Recovery: snapshot boleh transient/cache tetapi harus mampu memulihkan state valid setelah crash; tidak boleh menggantikan source project diam-diam.
DATA-005 — Cache: thumbnails/proxy/index/engine cache boleh diregenerasi dan bukan source of truth.
DATA-006 — Schema: project format harus versioned; migration behavior eksplisit. Detail schema bukan keputusan STEP 01.
