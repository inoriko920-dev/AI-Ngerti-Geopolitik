1. Ringkasan Eksekutif
AI Ngerti Geopolitik adalah aplikasi desktop Windows untuk menyusun video 
geopolitik/dokumenter secara otomatis dari input yang sudah terstruktur, lalu memberi 
pengguna kendali manual untuk mengoreksi hasil sebelum render final. Fokus produk bukan 
menyediakan semua fitur editor video umum, melainkan mempercepat pekerjaan berulang 
yang khas pada produksi video naratif: memetakan Scene ke aset, mengatur pacing, memberi 
motion yang konsisten, menampilkan subtitle, memasang narasi, melakukan validasi, dan 
mengekspor video dengan hasil stabil.
Repo lama membuktikan kebutuhan produk dan sudah memiliki banyak fitur penting, tetapi 
terlalu banyak subsistem editor dibuat sendiri: timeline interaction, preview, compositing 
scene, graph FFmpeg, motion, navigation, dan sejumlah behavior UI. Akibatnya jumlah kode 
presentation/timeline menjadi besar, preview dan final render mempunyai implementation 
path berbeda, serta test yang hijau belum otomatis membuktikan workflow nyata pada proyek 
panjang dan media beragam.
Strategi repo baru adalah memisahkan “hal yang unik bagi produk” dari “masalah multimedia 
umum”. Hal unik—Scene DOCX, Asset ID Axxx, aturan visual dokumenter, AI planning, 
validation khusus workflow, dan UX otomatis—tetap menjadi milik AI Ngerti Geopolitik. Hal 
umum—clip, track/layer, keyframe, playback, audio mixing, render timeline—ditopang engine 
matang, dengan libopenshot sebagai kandidat engine utama dan openshot-qt sebagai referensi 
editor infrastructure.
HASIL YANG DIINGINKAN — Pengguna dapat memasukkan materi video geopolitik, menekan 
alur otomatis, melihat timeline yang nyata, melakukan koreksi manual bila perlu, lalu 
mengekspor video final tanpa harus memahami FFmpeg atau menyusun setiap aset satu per 
satu.
1.1 Definisi sukses produk
 Cepat digunakan: project dapat dibuat dari Scene DOCX + folder aset tanpa setup teknis 
rumit.
 Stabil: workflow panjang tidak bergantung pada ratusan helper UI/timeline buatan sendiri 
yang saling menempel.
 Deterministik: keputusan AI diterapkan sebagai command tervalidasi dan dapat di-Undo.
 Preview dapat dipercaya: preview dan export memakai data timeline/transform yang sama
sehingga perbedaan visual diminimalkan dan didokumentasikan.
 Recoverable: crash, asset berpindah, request AI gagal, atau render dibatalkan tidak merusak
project sumber.
 Portable: user dapat memakai build Windows tanpa lingkungan developer.
 AI-friendly: struktur repo, dokumentasi, kontrak command, dan test membuat AI lain dapat 
melanjutkan tanpa menebak owner logic.

2. Masalah yang Ingin Diselesaikan
2.1 Masalah pengguna
Produksi video geopolitik/dokumenter sering berisi pola yang berulang: naskah dipecah 
menjadi scene, setiap scene mempunyai satu atau dua visual utama, visual perlu diberi motion 
agar tidak statis, narasi dan subtitle harus sinkron, dan seluruh scene perlu disusun menjadi 
video yang ritmenya terasa natural. Bila dikerjakan manual di editor umum, pengguna 
menghabiskan banyak waktu untuk operasi mekanis yang sebenarnya dapat diprediksi dari 
struktur naskah dan aset.
 Memasukkan puluhan/ratusan aset satu per satu dan memastikan urutannya benar.
 Menyesuaikan durasi scene berdasarkan konteks narasi.
 Menghindari animasi yang terlalu repetitif atau terlalu agresif.
 Mengatur dua visual dalam satu scene dengan framing yang konsisten.
 Mengelola subtitle, narasi, dan timing sambil tetap menjaga keterbacaan.
 Mengoreksi missing asset atau file yang berpindah tanpa membangun project ulang.
 Menunggu render atau request AI tanpa membuat UI hang.
 Memastikan project dapat dilanjutkan setelah aplikasi tertutup/crash.

2.3 Problem statement resmi
PROBLEM STATEMENT — Bagaimana membuat editor otomatis khusus video geopolitik yang 
mempertahankan workflow efektif dari AAVC, tetapi mengganti pondasi multimedia yang rapuh 
dengan engine matang sehingga aplikasi benar-benar stabil untuk project nyata, AI dapat 
mengambil keputusan editing yang tervalidasi, dan pengguna tetap memiliki kontrol manual 
serta recovery yang dapat dipercaya?
2.4 Yang TIDAK dianggap solusi
 Menambah lebih banyak helper di atas timeline custom lama.
 Menganggap “semua unit test lulus” sebagai bukti aplikasi siap dipakai.
 Memberi AI akses bebas untuk memodifikasi JSON project tanpa schema/validator.
 Meng-copy seluruh OpenShot lalu mengganti logo tanpa memisahkan kebutuhan produk.
 Mengejar semua fitur Filmora/Premiere yang tidak berhubungan dengan workflow 
geopolitik.
 Menambahkan provider AI lain sebelum Gemini flow stabil dan teruji.

3. Visi Produk dan Prinsip Desain
3.1 Visi
“AI Ngerti Geopolitik” harus terasa seperti asisten editor yang memahami struktur video 
dokumenter: ia menerima materi yang sudah dipetakan, menyusun draft edit secara masuk 
akal, menjaga visual tidak membosankan, dan mengerjakan pekerjaan teknis repetitif. 
Pengguna berperan sebagai director/reviewer, bukan operator yang harus mengatur setiap 
keyframe dari nol.
3.2 Prinsip produk
Prinsip Makna operasional
Automation first, manual correction second Default flow menghasilkan draft otomatis; semua 
keputusan penting tetap dapat dikoreksi manual.
Stable foundation over clever custom code Pilih engine yang sudah menyelesaikan 
playback/timeline/render daripada membangun ulang.
One canonical timeline Durasi, posisi, layer, transform, dan timing tidak boleh 
mempunyai versi berbeda antara preview dan export.
AI plans, validators decide AI mengusulkan command; aplikasi memvalidasi 
legalitas sebelum mutasi state.
Everything important is undoable Satu niat user/AI = satu transaction history yang jelas.
Fail closed Missing input, invalid media, credential unavailable, 
atau unsupported action harus menghentikan aksi 
secara jelas; tidak membuat output palsu.
Specialized, not bloated Setiap fitur harus menjawab workflow 
dokumenter/geopolitik.
Documentation is part of architecture Keputusan penting, schema, commands, dan ownership 
ditulis agar AI lain tidak membuat parallel 
implementation.
3.3 Prinsip teknis
 Tidak ada business rule di widget Qt.
 Tidak ada raw API key di project, log, screenshot, atau error text.
 Tidak ada long-running media/AI job pada GUI thread.
 Tidak ada direct mutation dari respons AI ke timeline engine.
 Tidak ada renderer alternatif tersembunyi yang menghasilkan hasil berbeda tanpa test 
parity.
 Tidak ada hard-coded developer path.
 Tidak ada dependency baru tanpa alasan, lisensi, pin versi, dan test.

5. Scope V1, Non-Scope, dan Roadmap
5.1 Scope V1 — harus selesai
 Create/Open/Save/Save As project yang aman dan atomic.
 Import Scene DOCX dengan mapping aset Axxx dan validasi structure.
 Asset browser/binding status READY/MISSING/CORRUPT/DUPLICATE serta relink.
 Timeline nyata dengan reorder, resize duration, split, selection, In/Out, marker, snap, zoom, 
follow playhead, navigator, Undo/Redo.
 SINGLE/DOUBLE scene workflow yang setara dengan kebutuhan lama.
 Manual animation/motion + deterministic random animation + lock per asset.
 Subtitle SRT import/edit/timing tools/style/animation/preset dan burn-in/export behavior.
 Narration import + microphone recording + project binding.
 Gemini credential secure slots 1–100 dan rotating pool.
 AI Auto Edit minimal yang aman: animation + pacing/transform command yang telah 
dibuktikan engine dapat render dan undo.
 Validation Center, project recovery/autosave, diagnostics.
 Export project/selection: H.264/H.265, 1080p/1440p/4K, 30/60 fps, quality preset, sharpen yang
benar-benar didukung.
 Windows portable build + clean-machine smoke test.
 Legacy AAVC project importer bila schema sumber valid; tidak mengubah file lama.

 Color grading profesional setara DaVinci Resolve.
 Fusion/VFX node graph.

 Cloud collaboration/multi-user.
 Mobile/Android build.
 Plugin marketplace.
 Provider AI selain Gemini kecuali ada keputusan baru.
 Generative image/video di dalam editor sebagai requirement V1.

7. User Journey End-to-End
7.1 Flow membuat project baru
 User memilih “Proyek Baru”.
 Aplikasi meminta Scene DOCX. Jika DOCX tidak dapat dibaca atau tidak memenuhi contract 
minimum, flow berhenti dengan error yang dapat ditindaklanjuti.
 Aplikasi meminta folder aset. Aset dipindai, di-hash/probe bila diperlukan, lalu dipetakan ke 
ID canonical.
 Aplikasi menampilkan review import: jumlah scene, jumlah aset, missing/duplicate/corrupt, 
dan perkiraan durasi.
 Opsional: user menambahkan narration audio dan SRT.
 User memilih lokasi project. Project disimpan secara atomic sebelum dianggap active session.
 Timeline canonical dibangun dari project model dan engine adapter.
 Editor terbuka dengan scene pertama terpilih dan validation badge live.
7.2 Flow AUTO EDIT
 Preflight memeriksa project siap: tidak ada blocker input, engine tersedia, credential Gemini

13. Preview, Playback, dan Sinkronisasi
13.1 Target preview
Preview harus membaca runtime timeline yang berasal dari ProjectState yang sama dengan

13.2 Playback behavior
 Play/pause/seek tidak memblok UI.
 Playhead time disimpan dalam satu canonical time representation.
