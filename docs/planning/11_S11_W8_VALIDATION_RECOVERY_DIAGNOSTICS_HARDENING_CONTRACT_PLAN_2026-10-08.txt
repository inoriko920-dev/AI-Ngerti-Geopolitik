6. VALIDATION MODEL
===================
ValidationIssue adalah immutable application DTO dengan minimum:
- issue_code
- severity: BLOCKER | ERROR | WARNING | INFO
- scope: PROJECT | MEDIA | TIMELINE_SCENE | SUBTITLE | NARRATION | AI | RENDER | RUNTIME
- safe_title
- safe_message
- target_ids
- remediation_action
- project_revision

Aturan:
- Message selalu menjawab what happened + where + next action.
- Severity tidak boleh color-only.
- Result bound ke revision tertentu.
- Setelah revision berubah, result lama = STALE sampai revalidate.
- Asset.availability tetap canonical online/offline/missing.
- CORRUPT/DUPLICATE adalah derived validation/media-health projection pada W8, bukan availability truth baru.

7. RELINK MATCHING CONTRACT
===========================
Ranking candidate deterministic:
1. exact canonical Axxx basename + probe-compatible;
2. exact original source_name basename + compatible media family/metadata;
3. exact SHA-256 fingerprint;
4. compatible metadata candidate -> manual choice only.

Safety:
- Similar filename saja tidak pernah cukup untuk auto relink.
- High-confidence candidate boleh preselected, tetapi commit tetap memerlukan explicit confirmation.
- Wrong media type / incompatible probe = hard reject.
- Single confirmed relink = one CommandBatch.
- Multi confirmed relink = one intentional batch transaction.
- Relink preserves asset_id dan clip references.
- path_ref/source_name/fingerprint/file_size/probe metadata/availability diperbarui dari verified probe.

8. RECOVERY CONTRACT
====================
- Autosave tetap terpisah dari canonical source.
- New snapshot identity: project_id + revision + timestamp; semantic hash metadata tetap dipakai.
- Existing revision/hash snapshot naming tetap discoverable untuk backward compatibility.
- Default retention: max 20 validated managed snapshots per project.
- Prune hanya managed autosave project terkait; source .angproj/.bak tidak disentuh.
- Crash/unclean marker + valid newer candidate -> recovery decision.
- Tidak ada valid candidate -> jangan tampilkan fake recovery.
- Recovery UI menampilkan source, timestamp/age, revision, validation status.
- Explicit actions: Open Source / Recover Snapshot / Ignore.
- Recover Snapshot membuka working state; source tidak ditimpa sampai user Save.
- Corrupt candidate di-skip/report; tidak menghapus source atau candidate lain.

9. DIAGNOSTICS CONTRACT
=======================
Structured event minimum:
- timestamp
- severity
- subsystem
- action
- job_id jika relevan
- project_id + revision jika relevan
- safe_error_code

Diagnostic bundle boleh memuat:
- app version / commit / engine versions
- sanitized OS/CPU/GPU summary
- bounded recent redacted logs
- project schema summary
- validation summary
- deterministic manifest

Dilarang default:
- raw API key / credential value
- full prompt
- full subtitle/narration content
- media bytes
- unnecessary user identifiers
- raw absolute path jika dapat direduksi/redact

Bundle generation yang non-trivial harus background-safe.

12. FAILURE INJECTION MATRIX
============================
- Referenced asset deleted after open -> BLOCKER, no crash, no clip deletion.
- Two plausible same-name relink candidates -> no auto apply.
- Wrong media type candidate -> reject zero mutation.
- Project changes while relink scan runs -> STALE cannot commit.
- Corrupt autosave -> skip/report; source/.bak untouched.
- Unclean marker + valid newer snapshot -> recovery choice.
- Unclean marker + no valid snapshot -> normal source, no fake recovery.
- Failure after temp write before replace -> prior source bytes exact.
- Diagnostic bundle unreadable temp/log -> safe typed failure, project unaffected.
- Diagnostic bundle secret scan -> no raw credential/key.
- Validation projection after revision change -> STALE until revalidate.
