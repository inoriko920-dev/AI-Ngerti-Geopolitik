3. WHY LIBOPENSHOT
LGPL-3.0 component; Python bindings; Timeline/Clip/KeyFrame/QtPlayer/FFmpegReader/Writer/audio mixing; active v1.0.1 release; Windows build docs; high UI freedom. Main risk: native Windows packaging and long-project runtime are NOT TESTED in ANG.

4. WHY MLT IS FALLBACK
Very mature multitrack engine, current v7.42.0, Python mlt7 bindings, proven through Shotcut/Kdenlive. More complex plugin/module license and Windows Python packaging surface.

5. WHY FULL EDITOR FORKS ARE NOT BASE
AAVC UI is locked 1:1. Full OpenShot/Shotcut/Kdenlive forks would import different UI, unrelated features, larger maintenance debt, and GPL app-code obligations. OpenCut is MIT but currently in ground-up rewrite.

6. LICENSE GATE
libopenshot LGPL-3.0-or-later candidate; openshot-qt GPL-3.0-or-later reference/HOLD; MLT core/framework LGPL-2.1 with module-specific variation; Shotcut/Kdenlive GPLv3; OpenCut MIT. Engineering screening only; final bundled binary/module obligations must be reviewed later.

7. WHAT REMAINS TO PROVE
Windows portable packaging; Python binding loading; seek/playback stability on 100–300 scenes; preview/export parity; 21 animation mapping; FFmpeg/Qt DLL notices; possible MLT comparative spike.

8. IMPACT ON STEP 03
Inventory AAVC UI-001..042 and current PySide6 screens/states. Do not redesign. Any necessary difference must be marked DELTA_FROM_AAVC.
