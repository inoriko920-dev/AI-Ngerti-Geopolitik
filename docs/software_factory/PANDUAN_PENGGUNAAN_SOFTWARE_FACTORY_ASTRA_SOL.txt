1. BACA INI DULU
Empat aturan yang membuat seluruh sistem tidak membingungkan.
ATURAN #1 — DOCX dan TXT berbeda fungsi
DOCX adalah manual untuk kamu. TXT adalah prompt operasional yang dikirim ke AI. Secara default, 
jangan kirim DOCX jika TXT tersedia dan isinya memang sama untuk eksekusi.
ATURAN #2 — HANYA SATU STEP AKTIF
Jangan mengirim seluruh STEP 00–15 untuk dikerjakan sekaligus. Kirim MASTER TXT + TXT STEP yang 
sedang aktif + evidence yang memang dibutuhkan. Setelah gate STEP itu selesai, baru pindah ke STEP 
berikutnya.
ATURAN #3 — ASTRA MERENCANAKAN, SOL MENGERJAKAN
STEP 00–07 dipimpin ASTRA. Mulai STEP 08, SOL menjadi pelaksana utama. ASTRA dipanggil kembali 
hanya saat ada keputusan besar, review UI/arsitektur, atau perubahan yang berdampak luas.
ATURAN #4 — UI GAMBAR ADA DI STEP 04
STEP 03 menentukan daftar UI; STEP 04 membuat prompt UI dan GPT benar-benar membuat 
gambarnya; STEP 05 mengunci gambar final; STEP 08 memasukkan reference pack ke GitHub; STEP 09 
SOL mengimplementasikan UI nyata dan membandingkan screenshot aktual dengan reference.
Pola paling sederhana yang perlu kamu ingat:
MASTER TXT + PROMPT STEP AKTIF + INPUT/EVIDENCE
 ↓
 ASTRA atau SOL bekerja
 ↓
 Gate + handoff + evidence

Apa yang dilakukan di STEP 03?
 Belum membuat gambar final.
 ASTRA memberi ID seperti UI-001, UI-002, dst.
 ASTRA mendaftar state: default, empty, loading, error, success, dialog, menu, settings, first-run, dll.
 ASTRA membuat UI_IMAGE_COVERAGE_MATRIX: mana yang wajib gambar P0/P1 dan mana yang 
cukup spec.
Apa yang dilakukan di STEP 04?
1. ASTRA membuat UI Bible/design system.
2. ASTRA membuat prompt gambar khusus setiap screen/state yang membutuhkan visual reference.
3. Prompt tersebut dijalankan dengan GPT Image/image generation tool.
4. Gambar candidate dinilai terhadap requirement dan design system.
5. Jika kurang sesuai, prompt direvisi dan gambar di-generate ulang.
6. Kamu memilih/menyetujui gambar final untuk UI penting.
7. Prompt revision dan final image diberi ID sehingga dapat dilacak.
Jika gambar banyak
Boleh membuat per batch, misalnya 10 UI per batch. Contoh: Batch 1 UI-001–UI-010, Batch 2 UI-011–
UI-020. Namun STEP 04 belum selesai sebelum semua P0/P1 yang diwajibkan coverage matrix memiliki 
final image.
Contoh perintah ke ASTRA pada STEP 04
PERAN AKTIF: ASTRA.
Kerjakan STEP 04 berdasarkan UI inventory dan reference yang sudah ada.
Buat design system dan prompt gambar untuk SEMUA UI/state P0/P1.
Setelah prompt siap, gunakan GPT Image untuk benar-benar membuat gambarnya.
Jika jumlahnya banyak, pecah per batch 10 gambar.
Review hasil, revisi prompt dan regenerate bila belum sesuai.
Jangan menyatakan STEP 04 PASS hanya karena prompt sudah ditulis.
Jika kamu ingin generate secara manual per batch
“Baca prompt UI Batch 1. Buatkan 10 gambar dari 10 prompt tersebut.
Jangan mengubah design system. Setiap gambar harus sesuai UI_ID dan state yang tertulis.”
Setelah selesai:
“Review 10 gambar Batch 1 terhadap prompt dan design system.
Tandai APPROVED atau REVISE. Untuk yang REVISE, perbaiki prompt dahulu sebelum generate ulang.”

GitHub tetap boleh ada sejak awal sebagai repo kosong/baseline, tetapi jangan menjadikan GitHub 
tempat AI menulis file satu per satu sambil masih berpikir. STEP 08 adalah titik ketika keputusan 
produk, UI, arsitektur, dan repository contract sudah cukup matang untuk foundation resmi.
Kalau kamu tidak mau mencoba di laptop
 Gunakan GitHub Actions/CI untuk lint, test, Windows build, screenshot UI, visual comparison, dan 
portable ZIP sejauh memungkinkan.
 Kamu cukup melihat screenshot, logs ringkas, artifact, dan status PASS/FAIL.
 Hal yang CI tidak bisa buktikan harus diberi status NOT_TESTED/BLOCKED, bukan diklaim lulus.

10. KALAU CHAT PUTUS / GANTI AI / LIMIT HABIS
Jangan mengulang proyek dari awal. Lakukan ini:
1. Buka repo/source-of-truth terakhir.
2. Ambil PROJECT_STATE/handoff terakhir, branch/SHA, task aktif, hasil test, blocker, dan next exact 
action.
3. Di chat baru, kirim MASTER TXT + prompt STEP aktif + state/handoff/evidence.
4. Tulis PERAN AKTIF yang sesuai.
5. Minta AI memverifikasi baseline sebelum melanjutkan.
Contoh:
“PERAN AKTIF: SOL. Lanjutkan proyek dari repo dan handoff terbaru.
Baca MASTER + prompt STEP 11. Verifikasi branch/SHA/status aktual dahulu.
Jangan ulang dari nol dan jangan menganggap chat lama tersedia.
Lanjutkan task READY berikutnya dan perbarui evidence + handoff.”

12. YANG JANGAN DILAKUKAN
 Jangan mengirim semua prompt STEP sekaligus dan berkata “kerjakan semuanya”.
 Jangan menyuruh SOL coding besar sebelum STEP 05–07 cukup matang.
 Jangan menganggap prompt UI = gambar UI final.
 Jangan freeze UI tanpa generated final image untuk screen/state P0/P1 yang diwajibkan.
 Jangan membiarkan SOL redesign UI frozen karena “lebih bagus menurutnya”.
 Jangan menganggap build hijau = aplikasi sudah benar.
 Jangan menyimpan API key/token/password di source, prompt, screenshot, artifact, atau repo.
 Jangan push perubahan setengah matang file demi file hanya karena bisa memakai API GitHub.
 Jangan membuat helper/service/class baru sebelum SEARCH UNDERSTAND MODIFY. → →
 Jangan meminta kamu sendiri memasang tooling developer hanya untuk menolong AI jika CI dapat 
mengerjakannya.
 Jangan mengulang dari STEP 00 hanya karena chat/model berganti; gunakan baseline dan handoff.
13. TEMPLATE PERINTAH SIAP PAKAI
A. Memulai STEP baru dengan ASTRA
PERAN AKTIF: ASTRA.
Gunakan Software Factory. Baca MASTER dan prompt STEP [NOMOR] yang saya kirim.
Gunakan handoff/evidence terakhir sebagai baseline.
Kerjakan hanya STEP ini sampai gate lengkap. Jangan melompat ke STEP berikutnya.
Jika ada keputusan produk yang benar-benar perlu saya pilih, jelaskan dengan bahasa sederhana.
B. Memulai STEP baru dengan SOL
PERAN AKTIF: SOL.
Baca MASTER, prompt STEP [NOMOR], repo, dan handoff terbaru.
Verifikasi branch/SHA/status aktual dahulu.
Kerjakan task STEP aktif secara serial, jalankan test/CI yang relevan, simpan evidence, lalu perbarui state dan 
handoff.
Jangan redesign keputusan yang sudah freeze.

C. Meminta ASTRA review hasil SOL
PERAN AKTIF: ASTRA.
Review hasil SOL untuk [STEP/TASK] pada [branch/SHA].
Periksa evidence, risiko, UI/arsitektur/acceptance criteria yang relevan.
Berikan keputusan: APPROVED FOR SCOPE / CHANGES REQUIRED / INSUFFICIENT EVIDENCE.
Jika ada perbaikan, tulis instruksi yang bisa langsung dijalankan SOL.
D. Meminta generate UI per batch
PERAN AKTIF: ASTRA.
Kita berada di STEP 04. Gunakan design system dan UI coverage matrix yang sudah disepakati.
Siapkan Batch [X] berisi maksimal 10 UI/state berikut: [ID].
Untuk setiap ID, finalkan prompt gambar lalu gunakan GPT Image untuk menghasilkan gambarnya.
Jangan campur state/ID. Setelah generate, review setiap gambar dan tandai APPROVED/REVISE.
E. Memulai STEP 08 / memasukkan ke GitHub
PERAN AKTIF: SOL.
Kerjakan STEP 08. Verifikasi UI Freeze terlebih dahulu.
Masukkan prompt final, generated final UI images, UI_REFERENCE_MANIFEST, dan UI_FREEZE_MANIFEST ke repo 
target.
Commit/push sebagai satu checkpoint konsisten, catat SHA nyata, lalu siapkan repository foundation dan CI.
Jangan mulai STEP 09 sebelum reference pack di GitHub dapat ditelusuri ke SHA.
