# STEP 12-03G — Native Full HD image-media render and Windows RAM proof

Date: 9 October 2026, WIB. Owner-authorized Pilot A development only.
PR #20 remains Draft/unmerged. No portable or release.

## Implementation and test contract
- 16 different high-resolution original PNGs **at exactly 1920×1080** per project,
  with original gradient imagery, foreground stripes and ellipse shapes.
  16 different SHA-256 media identities and canonical HOLD clips.
- Two separate real Windows FFmpeg exports: 30 FPS and 60 FPS,
  each producing 32 H264 yuv420p 1920×1080 frames without audio.
- Verify every decoded frame's 3 sampled RGB pixels against the
  corresponding original image, ±35 per channel, as well as FFprobe's
  exact frame count, FPS and dimensions.
- Native RAM telemetry samples current Windows working sets in Python/Qt
  and tracked FFmpeg/FFprobe process IDs every ~40ms, requires both groups
  actually observed, and checks sampled combined working set <2 GiB.
  Archival JSON for each FPS is included with downloadable MP4 and SHA256.
- FFmpeg raw video decoding uses an on-disk temporary file rather than a
  large raw-video bytes object (avoids test-only >200MB memory spikes).
- All past native MP4, audio/SRT, cancellation, disk-pressure and
  120-distinct-image tests remain mandatory through native Windows workflow.
- No changes to frozen approved UI (42 references).
- No claim of photorealistic image corpus, sustained long-form 1080p
  100–300 media scenes, 4K, peak native allocator tracking, full
  Windows process-tree Job Object containment, transitions/animation,
  General Availability or portable build.
